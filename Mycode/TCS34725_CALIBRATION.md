# TCS34725 颜色传感器标定说明

> 位置：`Mycode/tcs34725.c` / `Mycode/tcs34725.h`（驱动）
> 适用：替换 1 号灰度传感器（GRAY1），SCL=PB9、SDA=PB4
> 写于：2026-08-30（含当日实测数据）

---

## 1. 串口输出格式

上电后每 200ms 串口打一行（main.c 已实现）：

```
TCS C:4120 R:3650 G:310 B:280 H: 8.0 S:0.82 V:0.89 -> RED
     │     │    │     │    │     │     │     │     │      └─ 当前判色结果
     │     │    │     │    │     │     │     │     └──────── V 亮度 0~1（黑最低，白最高）
     │     │    │     │    │     │     │     └────────────── S 饱和度 0~1（灰/白≈0）
     │     │    │     │    │     │     └──────────────────── H 色相 0~360（决定是什么彩色）
     │     │    │     │    │     └────────────────────────── B/G/R/C 四通道 16bit 原始值
```

标定只用 **H / S / V** 三个数。

---

## 2. 标定操作步骤

1. 给主控板供电，打开串口（115200），看到 `TCS34725 ONLINE, ID=0x44`。
2. 把 **黑、白、红、蓝**（以及比赛需要的其它颜色）**物体依次**放到传感器正下方。
3. 放稳后抄下串口行里的 H、S、V。**每种颜色多采 5 次取平均值**，更稳。
4. **白色必测**（黑/白分界靠它）。
5. 填入第 3 节的记录表。

> ⚠️ 三个"必须一致"：
> - 距离：传感器离物体距离 = 比赛实际安装距离（一般 1~2cm）
> - 光照：标定环境光 = 比赛环境光（天黑/灯不同，阈值就要重标）
> - 增益/积分时间：标定前后不要改 `TCS34725_Init` 里的默认值

## 4. 阈值定值方法

### 4.1 早期驱动逻辑（HSV 三段式，**已废弃**，`tcs34725.c` 的 `TCS34725_ClassifyColor`）

```
V < TCS_BLACK_V_THRESH → 黑；S < 阈值 → 灰/白；其余按 H 分段（红<15 橙<40 黄<70 绿<160 青<200 蓝<260 品红<320）
```

阈值定值原则：相邻两类实测值的中间值（具体做法见 9.3）。

### 4.2 ⚠️ 当前实测数据用 4.1 的逻辑会判错，原因：

| 问题 | 现象 | 后果 |
|---|---|---|
| 黑 S 偏高 | 黑 S=0.33 | 黑不会进"灰白"分支，H=30 被判成**橙** |
| 蓝 S 偏低 | 蓝 S=0.12 | 蓝几乎掉进"灰白"分支，S 阈值稍大就误判 |
| 黑/蓝 V 接近 | 黑 V=0.43 > 蓝 V=0.38 | **亮度分不开黑和蓝** |

→ **必须改用"色相优先"判色**（第 5 节），不要硬凑这 3 个宏。

## 5. 判色方案（黑 / 红 / 蓝 三色，白/灰并入"黑"）

> ★ **当前生效阈值 = 5.2 节（2026-09-28 实地重采，`tcs34725.h` 的 4 个宏）；5.0 / 5.1 是历史留档，不要照着调。**

✅ **2026-08-30 按键采样 24 次后重写 `tcs34725.c` 的 `TCS34725_ClassifyColor`**。采样实测：

| 颜色 | H | S | V | 备注 |
|---|---|---|---|---|
| 黑(8次) | ≈20 | 0.43~0.50 | 0.44~0.50 | |
| 红(9次) | 0~3.8 | 0.70~0.74 | 0.66~0.71 | 红色按了9次，无妨 |
| 蓝(8次) | **≈300** | **0.10~0.14** | **0.36~0.38** | ⚠️ H 不在蓝相区！ |

> **关键发现**：这个蓝物体反光弱，S 和 V 都很低，色相 H≈300 落在品红区——**用色相 H 怎么都判不对蓝**。所以最终改用 **S、V 分类，完全不用 H**。

当前实现与阈值见 5.2（08-30 那版的 `0.30 / 0.42 / 0.58` 已废弃）。

### 5.1 ★2026-09-15 复标定（板上 CAL 模式实测：LED 亮、增益 1x、50ms 积分，每色 5 次）

| 颜色 | C | R | G | B | S（范围 / 均值） | V（范围 / 均值） |
|---|---|---|---|---|---|---|
| 黑 | 13~17 | 9.2 | 7.0 | 6.0 | 0.300~0.375 / **0.349** | 0.571~0.647 / **0.604** |
| 红 | 31~40 | 27.6 | 15.2 | 14.4 | 0.464~0.500 / **0.479** | 0.758~0.800 / **0.779** |
| 蓝 | 25~27 | 15.4 | 13.4 | 13.8 | 0.125~0.133 / **0.130** | 0.577~0.600 / **0.588** |
| 白 | 98~107 | 45.4 | 44.4 | 35.2 | 0.213~0.234 / **0.225** | 0.423~0.443 / **0.436** |

- 当时结论：S 把四色分得干干净净（蓝 0.130 < 白 0.225 < 黑 0.349 < 红 0.479，两两不重叠），所以只用 S/V、不用 H，
  定出阈值 `0.17 / 0.65 / 0.70`（C 当时觉得受距离/环境影响大没敢用，2026-09-28 起用于分蓝/白，见 5.2）；
- 旧阈值 `0.30 / 0.42 / 0.58`（08-30 版）判错的原因：黑 S=0.35≥0.30 且 V≥0.58 → 判红；蓝 S<0.30 且 V≥0.42 → 判黑；
- ★LED 脚接 **3.3V** 才常亮（接 GND 是关断，踩过坑）。

### 5.2 ★★★ 2026-09-28 实地复标定（**当前生效**，4 个阈值）★★★

来源 `颜色传感器阈值.txt`（串口 `COL ...` 日志 1961 行，黑/红/蓝/白四段，增益 1x、50ms、灯光/距离同比赛）。
同色会重复打很多次、偶尔还串进上/下一色的几行，所以按 `(C,R,G,B)` 分组取出现最多的"主导簇"来统计。

| 颜色 | C | S（范围 / 均值） | V（范围 / 均值） |
|---|---|---|---|
| 蓝 | 15~30 / **18.4** | ≤0.333 / **0.141** | 0.333~0.429 / **0.380** |
| 白 | 84~115 / **103.7** | 0.270~0.361 / **0.303** | 0.370~0.396 / **0.378** |
| 黑 | 10~18 / **11.6** | 0.400~0.600 / **0.470** | 0.417~0.545 / **0.483** |
| 红 | 20~36 / **28.7** | 0.667~0.762 / **0.724** | 0.618~0.724 / **0.687** |

**两个关键结论（和 09-15 那次完全不同）：**
1. **红/黑分界 0.70 → 0.58**：这批灯下红的 V 只有 0.62~0.72（上次 0.76~0.80），被 `TCS_BLACK_V_THRESH=0.70`
   整片切到 BLACK —— 409 个红样本里 360 个判黑，回家阶段就是"一直判黑、进不去红/蓝区"（全量错 21.5%）。
2. **蓝/白 靠 S 分不开**：蓝 S≤0.333、白 S≥0.270 已经重叠，但两者 **C 差 3 倍**（蓝 ≤30 / 白 ≥84）⇒
   低饱和分支里改用 C："**暗=蓝 / 亮=白·灰**"，门槛 50 卡在 30 和 84 中间（没这一刀，563 个白样本全判蓝）。
   S 阈值则取"蓝主导簇上沿 0.286 ↔ 黑下沿 0.400"的中点 0.34。

**当前阈值（`tcs34725.h`，规则见 `TCS34725_ClassifyColor`）：**

```c
#define TCS_BLUE_S_MAX     0.34f   /* 低饱和分界：蓝 S≤0.333，黑 S≥0.400 */
#define TCS_BLUE_V_MAX     0.50f   /* 低饱和里要够暗才算蓝（蓝 V≤0.429） */
#define TCS_WHITE_C_MIN    50.0f   /* 低饱和里 C 大于此=白/灰判黑（蓝 C≤30，白 C≥84） */
#define TCS_BLACK_V_THRESH 0.58f   /* 有彩色里 V 低于此判黑（黑 V≤0.545，红 V≥0.618） */
```

```
低饱和 s < 0.34 ┬ 又暗 c < 50 且又低亮 v < 0.50  → BLUE
                └ 否则（亮=白/灰，不参与比赛）  → BLACK
有彩色          ┬ v < 0.58                      → BLACK
                └ 否则                          → RED
```

**全量回代（1961 点）：新阈值错 2（0.1%）；旧阈值错 422（21.5%）：**

| 采样段 | 应判 | 新阈值 | 旧阈值 |
|---|---|---|---|
| 红 409 | RED | RED 409 ✅ | BLACK 360 / RED 49 ❌ |
| 蓝 480 | BLUE | BLUE 479 / RED 1 | BLACK 61 / BLUE 419 |
| 黑 489 | BLACK | BLACK 488 / BLUE 1 | BLACK 488 / BLUE 1 |
| 白 583 | BLACK（约定） | BLACK 583 ✅ | BLACK 583 |

> 新阈值那 2 个"错"是日志里串进来的别的颜色的行（蓝段混过 1 行 C=29 红数据、黑段混过 1 行 C=18 蓝数据），不是真判错。

**现场微调（改 `tcs34725.h` 重编译）：** 红判黑 → 调大 `TCS_BLACK_V_THRESH`；黑判红 → 调小；
蓝判黑 → S 超了调大 `TCS_BLUE_S_MAX`、C 超了调大 `TCS_WHITE_C_MIN`；白/反光判蓝 → 调小 `TCS_WHITE_C_MIN`。
⚠️ 阈值绑定了采样时的灯光/距离（C 是绝对亮度），换场地灯、改离地高度、或把 LED 从 3.3V 改 GND 都要按第 9 节重采重定。

## 6. 标定完成后自检

把每种物体再放一遍，看串口 `->` 后面的结果：
- 全对 → 收工；
- 红判成黑 → 调大 `TCS_BLACK_V_THRESH`；黑判成红 → 调小；
- 蓝判成黑 → S 超了调大 `TCS_BLUE_S_MAX`、C 超了调大 `TCS_WHITE_C_MIN`；白/反光面判成蓝 → 调小 `TCS_WHITE_C_MIN`；
- 蓝物体怎么调都判红 → 它的 S 太高，先改物理条件（贴更近、遮环境光、换更"正"的物体）。

## 7. 注意事项 / 常见坑

1. **白色没测之前黑白分界无法定**：务必补测白色。
2. **蓝 S=0.12 太低**：说明蓝物体反光弱、颜色发灰。优先检查：
   - 距离太远 → 贴近到比赛距离
   - 环境光太强/反光 → 用模块板载 LED 补光（把模块 LED 脚接 3.3V，或接 GPIO 输出高电平）
   - 换一个更"正"、更饱和的蓝物体
3. **C 值饱和**：白色 C 接近 20480（50ms/1x 增益时上限）就饱和，需降增益/积分时间；彩色 C 只有一两百就太暗，需提增益。
4. **标定环境光≠比赛环境光**：V/S 都会变，阈值失效。
5. 建议把标定数据（本节表格）填完后，在 `main.c` 的标定注释里注明日期和环境，方便回查。
6. **★"用着用着没反应 / 判色恒为同一种颜色"先查初始化**：2026-08-31 之后有一段时间
   `main.c` 上电处的 `TCS34725_Init();` 跟着调试循环一起被注释掉了 → PB4(SDA) 停在 CubeMX
   配的"输入上拉"，主机拉不低 SDA，I2C 全失败、C/R/G/B 全 0 → `ClassifyColor()` 恒判 **BLUE**，
   回家阶段"等到黑/红蓝才停"全部判错。现已修复：
   - `main.c` 上电处恢复显式初始化（含 3 次重试 + 串口打 `TCS34725 ONLINE, ID=0x44`）；
   - `TCS34725_GetRawData()` 内部加了 `tcs_ensure_ready()`，调用方漏了 Init 也会自动补。
   排查顺序：串口那行是 ONLINE 还是 OFFLINE → 查供电/接线（VCC=3.3V、SCL=PB9、SDA=PB4）
   → 再看这两个脚有没有被别的模块占用。

## 8. 如果还想更稳（可选进阶）

**模板匹配法**：标定时把每种颜色采多次，存平均 `rn/gn/bn`（`TCS34725_RGBC` 已算好，= R/C、G/C、B/C），运行时算欧氏距离取最近：

```c
/* dist = sqrt((rn-t.rn)^2 + (gn-t.gn)^2 + (bn-t.bn)^2) 最小者为该色 */
```

对"黑 S 高、蓝 S 低"这类不理想数据，模板匹配通常比任何阈值规则都稳。需要的话可以按这个思路单独写一个标定存储功能（存 flash 用工程里的 `myflash`/`storage`）。

## 9. ★★ 板上"颜色校准"模式（只采数据，阈值仍在代码里）★★

> 代码位置：`Core/Src/main.c` 的 `COLOR_Calib_Run()`。
> 设计：**不存 Flash、不改运行时逻辑** —— 阈值永远就是 `tcs34725.h` 的 4 个编译期宏
> （`TCS_BLUE_S_MAX` / `TCS_BLUE_V_MAX` / `TCS_WHITE_C_MIN` / `TCS_BLACK_V_THRESH`）；
> 这个模式只负责"把四种颜色的实测值打到串口"，拿回来按 9.3 重写宏、重新编译烧录。

### 9.1 怎么进

1. 开机进"红蓝方选择"界面，按 **KEY0** 循环切起始阶段，切到屏幕显示 `k3:GO CAL` + `color calib`；
2. 按 **KEY3** 进入（按 K3 返回菜单，**不会**往下走圆盘机/仓库等比赛阶段）。

### 9.2 按键与操作（顺序：黑 → 红 → 蓝 → 白，每种采 5 次）

| 屏幕 | 操作 | 按键 |
|---|---|---|
| `CAL BLACK` | 把**黑**物体放传感器下（距离=比赛距离、光=比赛光） | **K1**=切换颜色（黑→红→蓝→白→黑…，换色时计数清零）<br>**K2**=采样一次（打串口1 + 屏幕同步显示）<br>**K3**=返回菜单 |
| `CAL RED` / `CAL BLUE` / `CAL WHITE` | 换对应物体，各按 **K2** 采 5 次 | 同上 |

屏幕显示：当前颜色 / 上次采样的 `S V H` / `C R` / `G B` / `n=x`（该颜色已采次数）。
串口每次 K2 打一行（`#n` = 该颜色的第几次）：
```
CAL[BLACK] #1 C= 4210 R= 3592 G= 1180 B=  980 H=  20.0 S=0.451 V=0.472 -> BLACK
```

> 四色都采完（共 20 行）→ 把这 20 行 `CAL[...]` 发回来 → 按 9.3 的规则重写 `tcs34725.h` 的 4 个宏即可
> （想多采几轮更稳也行，按 `C R G B` 分组取占多数的那簇统计）。

### 9.3 拿到数据后怎么定阈值（人工，第 4/5 节规则的量化版）

```
TCS_BLUE_S_MAX     = (蓝.S最大 + 黑.S最小) / 2        // 低饱和(蓝/白/灰) ↔ 有彩色(黑/红) 分界
TCS_BLUE_V_MAX     =  蓝.V最大 + 余量(0.05~0.10)      // 低饱和里"够暗"才可能是蓝（防反光面）
TCS_WHITE_C_MIN    = (蓝.C最大 + 白.C最小) / 2        // ★低饱和里：暗(C小)=蓝，亮(C大)=白/灰
TCS_BLACK_V_THRESH = (黑.V最大 + 红.V最小) / 2        // 有彩色里：暗=黑，亮=红
```

- 每色先把 S、V、C 取平均（有异常值时改用"主导簇"范围），再套上面四式（分界取相邻两类的中点）；
- **白色必须测**（它是 `TCS_WHITE_C_MIN` 的依据）；**蓝/白 优先看 C，不要硬用 S 分**——两者 S 实测会重合
  （2026-09-28：蓝 0.333 / 白 0.270），C 却差 3 倍以上，落在"低饱和"侧的白/灰样本交给 `TCS_WHITE_C_MIN` 判黑；
- 定完自查：黑 `V<TCS_BLACK_V_THRESH`→`BLACK`；红 `V≥TCS_BLACK_V_THRESH`→`RED`；
  蓝 `S<TCS_BLUE_S_MAX` 且 `C<TCS_WHITE_C_MIN` 且 `V<TCS_BLUE_V_MAX`→`BLUE`；白按约定归 `BLACK`；
- 若两色实测挨得太近（例如 蓝.S 比 黑.S 还大），先改物理条件（贴更近、遮挡环境光、换更"正"的物体），别硬凑阈值。

### 9.4 注意

- 本模式**不写 Flash**、也不动判色逻辑（阈值就是 `tcs34725.h` 的 4 个宏，判色仍是 `TCS34725_ClassifyColor()` 的 S/V/C 判法）；
- 采数据时务必和比赛时**同样的距离/灯光**（见第 2 节"三个必须一致"），否则量出来的值没意义；
- 某一行如果打成 `READ FAIL (C=0)`，说明这次没读到（查 VCC=3.3V、SCL=PB9、SDA=PB4），该行不算数，重按 K2 即可。
