# 短距离移动可靠性改造 —— 启动同步 + 到位闭环（设计）

- 日期：2026-09-04
- 分支：wanyu
- 模块：chassis / robot
- 状态：已获用户批准（2026-09-04）

## 背景

自动分拣机器人走短距离（典型 15cm，比赛对位段 11.5cm / 3cm）时表现不可靠，
由队友反馈、作者返工。用户实测的典型故障：

1. **四个轮子先后转动**：某一轮已"到位"，另一轮还没开始转 → 距离时对时偏。
2. **干脆不动**：个别轮子从静止起转所需的 PWM 高于其他轮，短规划内爬不过去。
3. **偏多偏少**：停车是纯时间开环，实际位移随启动延迟/滑行漂移。

### 用户实测启动阈值（电机静止→持续转动，机器人悬空四轮不着地，PWM ±1000 系）

| 轮 | 编号 | 正转启动 PWM | 反转启动 PWM |
|---|---|---|---|
| 右前 RF | 4 | > +60 | < -70 |
| 右后 RB | 3 | > +80 | < -110 |
| 左后 LB | 2 | > +90 | < -130 |
| 左前 LF | 1 | > +110 | < -130 |

4 轮共用同一套增量式速度环 PID → 起动时 4 轮输出同步爬升，谁先越过自己的
静摩擦阈值谁先转，阈值差 = 启动时间差。此即"先后转"的根因。

### 关键现场数据（已确认）

- **`ENCODER_ACCURACY = 439` 是正确值**（用户确认：编码器倍数曾由 4 改 2 后标定所得），
  到位闭环的绝对距离精度前提已满足，**无需重新标定**。将来若更换轮径/编码器机械，
  再用文末复标公式校准。
- 起步存在轻微过冲/抖动：用户接受。

## 目标

对「从静止走一小段固定距离」这一场景，做到：

1. 4 轮**同时**破静摩擦起转，无先后、无"某轮没转另一轮已到位"。
2. 停车按**里程计真实位移**判定，堵转/启动延迟不再造成距离漂移。
3. 行为对长距离、斜走、原地旋转、定速移动（MoveSpeed）**无回归**。

## 非目标

- 不追求起步绝对平滑无抖动（起步一瞬过冲可接受，见上）。
- 不改造增量式 PID 本身（pid.c 防积死等逻辑不动，其他速度段依赖它）。
- 不改动 `ROBOT_Move / ROBOT_MoveSpeed` 接口，队友 main.c 比赛流程零改动。
- 不做逐轮落地静态阈值逐点重测（改由 margin 现场整定兜底，见 3.3）。

## 方案 A：轮级启动阈值表 + 输出整形（治"先后转 / 干脆不动"）

### A.1 数据结构

`chassis.h` 新增：

```c
/* 启动阈值整形（短距离从静止起转可靠性） */
typedef struct{ int16_t fwd; int16_t rev; } StartPwm_t;   // 正/反转启动 PWM 绝对值
#define START_PWM_MARGIN_DFT 1.5f  // 起转裕量默认值（chassis.start_margin 启动时取它，可在线调）
#define START_STILL_SPD       1.0f // 判定"轮子还没转起来"的实测速度阈值 cm/s
```

`chassis.c` 新增静态常量表（悬空实测值；索引 1~4 = LF/LB/RB/RF，与 TB6612/编码器/TIM1 一致）：

```c
static const StartPwm_t START_PWM[5] = {
    {0,0},   // 索引 0 不用
    {110,130},  // 1 左前（最难启动）
    {90,130},   // 2 左后
    {80,110},   // 3 右后
    {60,70},    // 4 右前（最好启动）
};
```

`Chassis` 新增字段：`float start_margin;`（默认 `START_PWM_MARGIN_DFT`，供落地现场在线整定）。

### A.2 整形点（控制循环内，每轮速度环 PID 之后、TB6612_Control 之前）

```c
float mrg = chassis.start_margin;
/* 该轮被命令要动(target 方向非零)且实测速度还很小(轮子没转起来)，
   且 PID 自身输出还不够 → 抬到"该轮自己的启动阈值×裕量"，
   让 4 轮在同一命令时刻各自够劲、同步破静摩擦 */
if(     pid->target >  0.5f && pid->actual <  START_STILL_SPD
     && pid->out < START_PWM[i].fwd * mrg){
    pid->out = START_PWM[i].fwd * mrg;
}else if(pid->target < -0.5f && pid->actual > -START_STILL_SPD
     && pid->out > -START_PWM[i].rev * mrg){
    pid->out = -START_PWM[i].rev * mrg;
}
```

要点：

- **同步机制**：每轮取自己的阈值，命令下达后各自一步抬到够转的 PWM，起转时间差从
  "阈值差"压到同一两个控制周期内。
- **不和 PID 打架**：仅当 `|actual| < START_STILL_SPD`（轮子没转起来）才抬 `out`；
  一旦 `|actual| ≥ START_STILL_SPD` 交还 PID。增量式下一拍 `out = 上一拍 + Δ`，
  破静摩擦后轮速冲高、误差反号，Δ 为负会把输出快速拉回，不会持续顶满。
  若轮子在起转后被 PID 压回静止（低速目标下存在 stiction 极限环可能），
  `|actual|` 回落 < 阈值会再次触发整形重新破静摩擦，属自愈行为，幅度受 10ms 周期约束。

### A.3 margin 落地整定（替代逐轮落地重测）

悬空阈值 < 落地阈值（轮胎-地面静摩擦更大），故落地真值由 `start_margin` 兜：

1. `start_margin` 先给 1.6~2.0（经 serialplot 在线下发，param 名见 5）。
2. 跑 15cm 前进，确认 4 轮**同时**起转、无某轮明显迟滞。
3. 逐步调小到"再小就会有轮滞后"的上一步，即为该车的落地 margin。
4. 若 margin 需 > 2.0 才同步 → 说明落地阈值显著高于悬空值，改为现场补测落地
   8 值直接写 `START_PWM` 表（A.1），一劳永逸。

margin 过大的代价 = 起步一瞬过冲（轮子转猛被 PID 拉回），用户已接受。

## 方案 B：到位闭环 —— 按里程计真实位移判停（治"偏多偏少"）

现状停车是纯时间开环：中断里 `ti >= tp.t` 清规划标志 → v 归零。改为
**车体坐标系内实际累计位移 ≥ 目标距离**即判停，时间开环降级为兜底。

### B.1 数据结构（Chassis 新增）

```c
float dist_acc_x;      // 本段规划已走距离 cm（车体系，fabs 累计，Start_Move 清零）
float dist_acc_y;
float move_target_x;   // 本段目标距离 cm = |x_dist|（Start_Move 记录）
float move_target_y;   // = |y_dist|
```

### B.2 累计点（CHASSIS_Odom_Calculate 内，dx_o/dy_o 已算出处）

```c
chassis.dist_acc_x += fabsf(dx_o);
chassis.dist_acc_y += fabsf(dy_o);
```

用麦轮正解的**车体系**位移而非全局 pos_x/pos_y：不依赖 yaw、无需把"起始车头方向"
投影出来；x/y 两轴各自独立判停，天然支持斜走。

### B.3 清零 / 记录（CHASSIS_Start_Move 内）

```c
chassis.dist_acc_x = 0.0f;  chassis.dist_acc_y = 0.0f;
chassis.move_target_x = fabsf(x_dist);
chassis.move_target_y = fabsf(y_dist);
```

### B.4 判停（控制循环规划执行段，与 `ti >= tp.t` 清标志同处）

```c
/* x 轴：目标距离 >0 且 累计已走 ≥ 目标 → 判停清标志（本周期即归零 v_x） */
if(chassis.x_speed_plan_flag && chassis.move_target_x > 0.1f
   && chassis.dist_acc_x >= chassis.move_target_x){
    chassis.x_speed_plan_flag = 0;
}
/* y 轴同理 */
if(chassis.y_speed_plan_flag && chassis.move_target_y > 0.1f
   && chassis.dist_acc_y >= chassis.move_target_y){
    chassis.y_speed_plan_flag = 0;
}
```

判停须在 `if(flag) v = dir*vel; else v = 0;` **之前**执行，使同一周期 v 就归零。
距离为 0 的轴 `move_target = 0` 跳过判停，维持原 `tp.t=0` 立即清标志的行为。
`ti >= tp.t` 原逻辑保留作**兜底**：全车真卡死（dist_acc 不涨）时靠时间退出，不死等。

### B.5 对既有模式的影响

| 模式 | 走 Start_Move? | move_target>0? | 影响 |
|---|---|---|---|
| ROBOT_Move（本方案场景）| 是 | 是 | 判停生效 |
| 斜走（x+y 同时动）| 是 | 双轴各自 >0 | 各轴独立判停，先到先停，剩轴续走 |
| ROBOT_MoveSpeed 定速 | 否（清了规划标志）| 不判（规划标志为 0）| 无影响 |
| 原地旋转 | 否 | 不判 | 无影响 |
| 串口 mx/my 平移 | 是 | 单轴 | 同 ROBOT_Move |

### B.6 ROBOT_Move

**无需改动**：它本就 `while(x/y_speed_plan_flag) HAL_Delay(5)` 阻塞，到位判停
在中断里清标志后自然退出。接口零变化。

> 到位后轮子仍有惯性会滑一点 → 沿用 robot.c 注释约定：调用侧按需补延时。
> 低速（≤40cm/s）滑行很小，比赛对位段本身有灰度/视觉触发兜底。

## 落地联调顺序

1. **margin 整定**（3.3）：serialplot 下发 `stm`，落地 15cm 前进找"4 轮同时起转 +
   不过冲"区间。
2. **重复性验证**：`ROBOT_Move(0,15,0,10,0,10)` 原地往返 ≥5 次，尺测 ±0.5cm 内；
   再跑比赛对位段（11.5cm、3cm）确认。
3. **回归**：长距离（>80cm）、斜走（x+y 同时）、原地旋转、ROBOT_MoveSpeed 定速
   各测一遍，确认无回归。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| margin 过小 → 某轮仍滞后 | 3.3 逐步上调；不行就落地补测 8 值写表 |
| margin 过大 → 起步过冲 | 用户接受；PID 反号快速收敛，过冲一瞬 |
| 低速目标下 stiction 极限环（小幅自愈抖动）| 10ms 周期约束幅度；属可接受抖动 |
| 判停绝对精度依赖 ENCODER_ACCURACY | 439 已确认正确；留复标公式（见下）备用 |
| 全车真卡死 dist_acc 不涨 → 判停永不触发 | `ti>=tp.t` 时间兜底保留 |

**复标公式（备用）**：`ENCODER_ACCURACY = 当前值 × 实测距离 / pos 读数`（地上贴
100cm 走完看里程计 pos_y）。

## 设计决策记录

- 同步手段选**每轮启动阈值表**（用户实测悬空 8 值直接用），否决 kick 脉冲/只加驱动力方案。
- 到位判停用**车体系累计位移**（麦轮正解处累加），否决全局 pos 投影（依赖 yaw、要投影）。
- 改动边界 = **同步 + 到位一起治**，且 `ROBOT_Move/ROBOT_MoveSpeed` 接口不变。
- 落地阈值不逐轮重测，改 **margin 现场整定**兜底（用户接受）。
- ENCODER_ACCURACY **不重新标定**（用户确认 439 正确）。
- 起步过冲抖动**可接受**（用户确认）。
