# 短距离移动可靠性改造 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让机器人从静止走一小段固定距离（典型 15cm）可靠：4 轮同步破静摩擦起转、停车按里程计真实位移判定，接口 `ROBOT_Move/ROBOT_MoveSpeed` 不变。

**Architecture:** 两层内部改造（均在 10ms 控制循环内）：① 启动整形——每轮用自己实测的静摩擦启动 PWM 阈值表，命令下达且轮子未转时把输出抬到「该轮阈值×margin」，四轮同一拍起转；② 到位判停——`CHASSIS_Odom_Calculate` 累加车体系实际位移，规划执行段当「累计位移 ≥ 目标距离」即清规划标志停车，原 `ti>=tp.t` 时间判停降级为卡死兜底。

**Tech Stack:** STM32F407 / HAL / 增量式速度环 PID / 麦轮底盘 / VSCode+CMake（`cmake --build --preset Debug` 编译）。无单测框架，验证 = 编译通过 + 板载实机联调。

**前置提醒（务必先做 Task 0）**：`git status` 显示 `Mycode/chassis.h`、`Core/Src/main.c`、`.clangd` 有**未提交改动**。提交时**只 `git add` 本功能涉及的文件**，绝不 `git add -A`，防止把队友的 main.c/.clangd 改动一起提交。

### Task 5: chassis.c —— 控制循环速度环后：启动阈值整形

**Files:**
- Modify: `Mycode/chassis.c`

- [ ] **Step 5.1: 4 轮速度环 for 循环内（254 行 `PID_IncUpdate(pid);` 与 255 行 `TB6612_Control(i, (int16_t)pid->out);` 之间）插启动整形：**

```c
    /* 启动阈值整形（2026-09-04 新增）：该轮被命令要动(target≠0)但实测速度还很小(轮子没转起来)、
       且 PID 自身输出不够 → 抬到"该轮自己的启动阈值×裕量"，让4轮同一命令时刻同步破静摩擦。
       轮子一旦转起来(|actual|≥START_STILL_SPD)立即交还 PID；增量式下一拍按误差把输出拉回，不会持续顶满 */
    float mrg = chassis.start_margin;
    if(     pid->target >  0.5f && pid->actual <  START_STILL_SPD
        && pid->out < START_PWM[i].fwd * mrg){
        pid->out = START_PWM[i].fwd * mrg;
    }else if(pid->target < -0.5f && pid->actual > -START_STILL_SPD
        && pid->out > -START_PWM[i].rev * mrg){
        pid->out = -START_PWM[i].rev * mrg;
    }
```
